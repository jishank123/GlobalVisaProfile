1. System Overview

🎯 Project Purpose

ImmigrationPro is a comprehensive client management system for immigration profile building and application services. It manages client assessments, services, payments, and queries with role-based access for admins, managers, and clients.

Key Features

✨ Core Capabilities

  • Profile Assessment Collection with Contact Info
  • Client Account Management
  • Service Progress Tracking (0-100%)
  • Payment History & Status Monitoring
  • Query/Support Ticket System
  • Account Manager Assignment (Optional)
  • Real-time Dashboard Updates
  • Contact Form & Appointment Submissions

User Roles

Role Access Level Primary Functions
Admin Full System Access View all data, assign managers, manage system
Account Manager All Clients (No Auth) View/update clients, services, payments, queries
Client Own Data Only View assessment, track services, check payments, submit queries

3. Database Design

Database Schema Overview

The system uses 8 primary tables to manage all data. Each table is designed with specific relationships and constraints to ensure data integrity.

Design Principles

🎯 Key Design Decisions

  • UUID Primary Keys: All tables use UUID strings for primary keys
  • Timestamps: All tables include created_at and updated_at fields
  • Soft Deletes: Records marked as deleted, not physically removed
  • Status Fields: Track record states (active, pending, completed, etc.)
  • Foreign Keys: Maintain relationships between tables
  • Nullable Fields: Optional data marked as nullable

Table Categories

Category Tables Purpose
Assessment & Lead Capture profile_assessments, contact_submissions, appointment_requests Capture client information from website forms
Client Management client_accounts Store authenticated client accounts
Service Tracking client_services Track services, progress, and milestones
Financial client_payments Payment history and balances
Support client_queries Client questions and admin responses
Staff Management account_managers Account manager profiles (optional)

4. Database Tables

📋 Table 1: profile_assessments
Field Name Type Key Description
id text PK Unique assessment ID (UUID)
client_name text - Client's full name
client_email text - Client's email address
client_phone text - Client's phone number
field_of_expertise text - Professional field (tech, science, arts, etc.)
years_of_experience number - Years of professional experience
current_location text - Current location (us/outside_us)
criterion_1_awards number - Score for Awards & Prizes (0-3)
criterion_2_memberships number - Score for Professional Memberships (0-3)
criterion_3_media number - Score for Media Coverage (0-3)
criterion_4_judging number - Score for Judging Others' Work (0-3)
criterion_5_contributions number - Score for Original Contributions (0-3)
criterion_6_publications number - Score for Scholarly Publications (0-3)
criterion_7_exhibitions number - Score for Exhibitions (0-3)
criterion_8_leadership number - Score for Leadership Roles (0-3)
criterion_9_salary number - Score for High Compensation (0-3)
criterion_10_commercial number - Score for Commercial Success (0-3)
overall_score number - Overall score percentage (0-100)
profile_strength text - Strength rating (Excellent/Strong/Good/Weak)
criteria_met number - Number of criteria strongly met
strong_criteria_count number - Count of strong criteria (score 3)
moderate_criteria_count number - Count of moderate criteria (score 2)
status text - Current status (new/contacted/qualified)
follow_up_status text - Follow-up status (pending/scheduled/completed)
created_at datetime - Record creation timestamp
updated_at datetime - Record update timestamp

💡 Purpose

Stores comprehensive EB-1A profile assessments completed by potential clients. This is the primary lead capture mechanism, collecting detailed information about the client's professional background and eligibility across all 10 USCIS criteria.

👤 Table 2: client_accounts
Field Name Type Key Description
id text PK Unique client account ID (UUID)
name text - Client's full name
email text - Email (used for login)
phone text - Contact phone number
password_hash text - SHA-256 hashed password
field_of_expertise text - Professional field
account_manager_id text FK Assigned account manager (references account_managers.id)
status text - Account status (active/inactive/suspended)
created_at datetime - Account creation timestamp
updated_at datetime - Last update timestamp

💡 Purpose

Manages authenticated client accounts. Clients can create accounts to access their personal dashboard, track services, view payments, and submit queries. The account_manager_id field links clients to their assigned account manager (optional).

💼 Table 3: client_services
Field Name Type Key Description
id text PK Unique service ID (UUID)
client_id text FK Client account ID (references client_accounts.id)
service_type text - Type of service (EB-1A, EB-2 NIW, O-1, etc.)
service_name text - Descriptive service name
status text - Service status (active/on_hold/completed/cancelled)
progress_percentage number - Progress percentage (0-100)
current_milestone text - Current phase/milestone description
start_date datetime - Service start date
expected_completion_date datetime - Expected completion date
actual_completion_date datetime - Actual completion date (when completed)
notes text - Internal notes about service
created_at datetime - Record creation timestamp
updated_at datetime - Record update timestamp

💡 Purpose

Tracks services purchased by clients. Each service has a progress percentage (0-100%) and current milestone, allowing clients and managers to monitor real-time progress. Multiple services can be assigned to a single client.

💳 Table 4: client_payments
Field Name Type Key Description
id text PK Unique payment ID (UUID)
client_id text FK Client account ID (references client_accounts.id)
service_type text - Service being paid for
total_amount number - Total service cost
amount_paid number - Amount paid to date
payment_status text - Status (paid/pending/partial/overdue)
payment_date datetime - Date of payment
payment_method text - Payment method (credit_card/bank_transfer/check)
created_at datetime - Record creation timestamp

💡 Purpose

Manages payment records for client services. Tracks total amounts, payments made, and outstanding balances. Clients can view their payment history, and managers can monitor payment status across all clients.

💬 Table 5: client_queries
Field Name Type Key Description
id text PK Unique query ID (UUID)
client_id text FK Client account ID (references client_accounts.id)
subject text - Query subject/title
message text - Query message/question
priority text - Priority level (high/medium/low)
status text - Query status (pending/resolved/closed)
response text - Admin/manager response
response_date datetime - Date response was provided
query_date datetime - Date query was submitted
created_at datetime - Record creation timestamp

💡 Purpose

Support ticket system for client questions and concerns. Clients can submit queries through their portal, and managers/admins can respond and mark them as resolved. Replaces email-based communication with organized ticketing.
